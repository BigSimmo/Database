# On Call hub — mockup conformance ledger

The record of how the built hub relates to the eleven artboards in
[`prototypes/on-call-screens.html`](prototypes/on-call-screens.html).

A mockup consulted once and then left behind is how a build drifts without anyone noticing: each
departure looks reasonable on its own, and the accumulated result is a page nobody drew. So this
file, not the drawing, is the record — and `tests/on-call-mockup-conformance.test.ts` keeps the two
in step. It fails if a board in the drawing has no row here, if a row names a board the drawing does
not contain, if a `built` row cites a testid no component declares, or if a `deviation` row does not
say why the drawing was not followed.

## How to read it

| Column          | Meaning                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Board**       | The artboard, named exactly as the drawing names it.                                                                                                                                             |
| **Element**     | One drawn thing: a module, a group, a chip row, a banner, a row treatment, an action.                                                                                                            |
| **Disposition** | `built` — it is on the page. `open` — accounted for and inside change A, not yet written. `deviation` — deliberately different, reason in the note. `change-b` — waiting on the database change. |
| **Where**       | For `built`, the testid that proves it. For `change-b`, the step in the change-B plan.                                                                                                           |
| **Note**        | Required for every deviation.                                                                                                                                                                    |

Changing a disposition is a decision, not bookkeeping. If the drawing itself changes, the boards
change here first and the test tells you what is now unaccounted for.
