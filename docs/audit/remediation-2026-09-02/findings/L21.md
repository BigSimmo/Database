`cacheIndexingVersion` is the corpus-staleness guard for both local and shared answer/search caches. A PostgREST error on the `documents` stamp query is folded into the same constant as a genuinely empty corpus (`no-indexed-documents`), cached for 5 s, and then used as the `indexing_version` for writes (`setCachedAnswer`, `setCachedSearch`, `replaceSharedCacheRow`) and reads (`sharedCacheSelector`). Unlike the thrown-exception path (:524, `index-stamp-unavailable`), the error-object path is indistinguishable from 'nothing indexed', and neither path refuses to write. **Impact:** An answer generated before a document change can be served with `answer_cache_hit` after the change, bypassing the guard that exists precisely to prevent that. Requires a double fault, so probability is low; consequence is a stale clinical answer with a clean-looking routing reason. **Fix:** Map `error` to the `index-stamp-unavailable` constant (distinct from empty corpus) and make `setCachedAnswer`/`setCachedSearch` return early when the stamp ends with `index-stamp-unavailable`; add a unit test in tests/rag-cache-invalidation.test.ts for the error branch.
