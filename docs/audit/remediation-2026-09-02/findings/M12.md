The _v2 wrappers (schema.sql:8075-8091, :8130-8155) delegate to the same bodies. publish_approved_documents, by contrast, nulls all eight child owners (:~8380).
- **Trigger:** An operator calls set_document_corpus_access_mode('public') on a corpus that contains owned (non-null owner_id) documents — the only situation the function exists for.
- **Impact:** For every previously-owned document, public/anonymous retrieval returns the document and its chunks (owner nulled) but get_related_document_metadata_v2 with the public sentinel finds no labels/summaries (rows still owned) and match_document_table_facts_text_v2 returns none of its table facts. Answer context silently lacks the summary/label/table-fact evidence the answer path uses for those documents — a fail-closed degradation, not an exposure. Latent today: the 2026-09-01 read in #ZBAC9D recorded 2851 documents all with owner_id NULL, so no current row is affected; the defect bites the first time the switch is used for its purpose. The 'private' restore path is unaffected (children were never changed).
