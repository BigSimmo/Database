### M21 · Blanket `Bash(git push:*)` allow lets force-pushes and pushes to main through without confirmation; deny rules are prefix-shaped only

`.claude/settings.json:147 (allow `Bash(git push:*)`) vs :17-33 (deny list)` · security · **CONFIRMED** · safe_cleanup=false · lane L20 (L20-F1) · corroborates #132 (resolved 2026-07-30 as an 'explicit limitation' of client-side push guards) — new evidence: the permission file itself now auto-allows the dangerous shapes; the row's premise that the pre-push hook is the backstop is weakened because `--no-verify` is also auto-allowed

- **Defect:** Claude Code Bash permission rules are prefix matches (as `tests/claude-code-settings.test.ts:41-47` documents). The deny list only names `git push --force`, `git push -f`, `git push --force-with-lease`, `git push origin main`, `git push origin HEAD:main` and their `master` twins. Any other spelling falls through to the allow rule and runs with no prompt: `git push origin --force <b>`, `git push origin -f <b>`, `git push origin +<b>` (refspec force), `git push origin +HEAD:main`, `git push -u origin main`, `git push --set-upstream origin main`, `git push origin feature:main`, `git push origin refs/heads/x:refs/heads/main`, `git push --delete origin <b>`, `git push origin :<b>`, `git push --mirror origin`, and `git push --no-verify origin <b>` (which also skips the repo's `guard-push.mjs` auto-merge/format/drift hook). PR #2243 loosened `git push` for routine work and the review only closed the `HEAD:main` shape.
- **Trigger:** An agent session (auto mode, or a normal session with these allow rules) composes any of the listed spellings — e.g. `git push origin +claude/x` after a rebase, or `git push -u origin main` by mistake — no confirmation is requested.
- **Impact:** History rewrite of a PR branch (can discard a commit GitHub already validated while auto-merge is armed — the exact race `guard-push.mjs` exists for), deletion of remote branches, or a direct push to `main` (which auto-deploys to Railway and, for `supabase/migrations/**`, applies to the live clinical database within seconds). GitHub's `Protections` ruleset on `main` is the only remaining barrier and its admin-bypass status was not verifiable offline.
- **Proof:** Ran the same prefix model as the committed test over 15 variants: `git push origin --force feature` deny=0 ask=0 allow=Bash(git push:_); `git push origin +HEAD:main` deny=0 ask=0 allow=Bash(git push:_); `git push -u origin main` deny=0 ask=0 allow=Bash(git push:_); `git push --delete origin feature` deny=0 ask=0 allow=Bash(git push:_); `git push --no-verify origin feature` deny=0 ask=0 allow=Bash(git push:*). `npx vitest run tests/claude-code-settings.test.ts` -> `Tests 109 passed (109)`, i.e. none of these shapes is pinned. `scripts/guard-push.mjs:143-152,293` blocks a force-push only when auto-merge is armed and only when the hook runs at all (`--no-verify` skips it; `core.hooksPath` is unset in fresh containers per `.claude/hooks/push-format-guard.sh:4-11`).
- **Fix sketch:** Replace the blanket allow with an explicit safe shape (e.g. `Bash(git push origin claude/*)`, `Bash(git push -u origin claude/*)`) and add deny/ask entries for `git push origin --force*`, `git push origin -f*`, `git push origin +*`, `git push -u origin main*`, `git push --set-upstream origin main*`, `git push origin *:main*`, `git push --delete*`, `git push -d*`, `git push --mirror*`, `git push --no-verify*`; extend the `dangerousPushCommands` table in `tests/claude-code-settings.test.ts:150` with these spellings so the test can fail.
- **Skeptic (CONFIRMED):** Reproduced with the repository's own documented prefix model: every listed spelling falls through to the blanket allow, including `+refspec` force pushes, `-u origin main`, `<src>:main`, branch deletion and `--no-verify` (which also skips guard-push.mjs).
