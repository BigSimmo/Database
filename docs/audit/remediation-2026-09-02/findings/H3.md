### H3 · clinicalOnly table cleaning drops header cells but not body cells, shifting clinical values under the wrong column heading

`src/components/AccessibleTable.tsx:130-132 (header .filter(Boolean) vs unfiltered body) and :172 (displayRows indexes body by header position)` · correctness · **CONFIRMED** · safe_cleanup=false · lane L13 (L13-F1)

- **Defect:** clinicalOnlyTable() cleans every kept header with cleanClinicalTableText() and then drops headers that clean to empty (`.filter(Boolean)`), but applies no matching drop to body rows. AccessibleTableMarkup then builds each display row as `header.map((_, index) => row[index])`, so once one header is removed every later body cell is read one position to the left and the last cell is silently discarded.
- **Trigger:** Any answer or visual-evidence table (output-panel.tsx:193, visual-evidence.tsx:162 both pass `clinicalOnly`) whose header cell is a metadata word plus a number — e.g. `Source: 3`, `Page 2`, `Citation 1`, `Chunk 4`. isMetadataHeader() only matches the bare word (`^source$` etc.), so such a header survives column removal and is then blanked by metadataCellPattern.
- **Impact:** A clinician sees a dose/level/interval printed under the wrong heading (e.g. the 'Max dose' column shows the source name) and the real value vanishes from the rendered table. This is the on-screen clinical table, not an export, and the low-confidence caveat is not raised because normalisation already succeeded.
- **Proof:** node replica of the exact regexes and the line-130/132 logic on header ['Drug','Source: 3','Max dose'] with rows [['Lithium','RANZCP','1200 mg'],…] produced header ['Drug','Max dose'] and unchanged 3-cell rows; with line 172's `header.map((_, i) => row[i])` the 'Max dose' cell renders 'RANZCP' and '1200 mg' is dropped. Not executed in the React component — traced.
- **Fix sketch:** Compute the kept indexes after cleaning (drop an index when its cleaned header is empty) and apply the same index list to body rows; or keep an empty header as `Column N` instead of filtering. Add a DOM test with a 'Source: 3' header asserting cell/heading alignment.
- **Skeptic (CONFIRMED):** Reproduced offline from the exact source regexes and lines; no unit test pins clinicalOnlyTable, and the normalizer upstream does not neutralise a 'Source: 3' / 'Page 2' / '<file>.pdf' header (only bare words are treated as metadata columns). Ledger grep for clinicalOnly/metadata column/GEN-H3 finds nothing. Runtime precondition is data-shaped (an answer or OCR table whose header cleans to empty) but plausible in both callers, and when it fires a signed-in clinician sees a dose under the wrong heading with no low-confidence caveat — the High criterion. Fix (compute kept indexes after cleaning and apply to body, or keep 'Column N') is local to the component and touches no RAG/ranking surface; the semgrep ReDoS hit at AccessibleTable.tsx:23 is a separate, unrelated pattern.
