- **Defect:** The drug-interaction evaluator reads data/medication-interaction-index.json, which is derived from data/medications-snapshot.json plus the lexicon. The freshness gate exists (build-medication-interaction-index.ts --check) and passed locally in this audit (531 rows), but it is wired only into verify:pr-local. CI runs the lexicon-report and therapy-index drift gates under the same static_heavy condition and skips this one; tests/medication-interaction-lexicon-coverage.test.ts:70-76 only checks the index against itself (row total vs its own sourceRowCount), never against the snapshot.
- **Trigger:** Any PR that edits data/medications-snapshot.json (new drug, changed Key Interactions row) or the lexicon without re-running `npm run medications:interactions`, pushed from an environment that skipped verify:pr-local (the bare-PR route in AGENTS.md explicitly permits this).
- **Impact:** New or renamed drugs would be absent from `names`/`bySlug`: evaluateMedicationInteractions reports dataAvailable=false (safe) for the viewed drug, but changed row text would render stale via `row.note` on the reverse path (medication-interactions.ts:292), and rows added to an existing drug would not alert at all. The therapy catalogue got exactly this gate in CI after the identical failure mode (#333 comment at ci.yml:230-233); the medication index did not.
- **Proof:** grep of ci.yml for `medication-interactions` returns nothing; `grep -o check:medication-interactions package.json | wc -l` = 1; no test file imports both medications-snapshot and medication-interaction-index (grep). The 2026-09-02 gate-consolidation audit inventories the gate as "local only, offline" (row 382) without raising it. Not executed in CI — traced.
- **Fix sketch:** Add `- name: Medication interaction index drift / if: static_heavy_changed / run: npm run check:medication-interactions` beside the lexicon step in ci.yml, and add it to verify:cheap:internal so check:gate-manifest counts it.
