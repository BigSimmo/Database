## 12. Never touch / not recommended — restated explicitly

Nothing below is a recommendation of this audit, whatever a finding's fix sketch might tempt a reader into.

- **The RAG ranking and evaluation surfaces** (`src/lib/rag/**`, `clinical-search`, `retrieval-selection`, `released-search-order`, `ranking-config`, the eval harness, aliases, golden fixture and retrieval RPCs). Several findings live in or beside these files (M-class items in `clinical-safety.ts`, `source-text-sanitizer.ts`, `ward-output.ts`, `rag-query-guard.ts`, `get_related_document_metadata`). Every fix there needs the `RAG impact:` PR line and, for any retrieval or ordering change, the provider-backed canary pair — the 2026-07-20 refuted-approaches record is why. This audit changed none of them and recommends none of them be changed without that process.
- **The ledgers and inbox.** `docs/outstanding-issues.md`, `docs/branch-review-ledger.md`, `docs/branch-review-records/**` and `docs/outstanding-issues-inbox/**` are never hand-edited. Where this audit says a row is stale, the action is `npm run issues:done` or `issues:update`, from the owner's triage, not an edit.
- **`check:gate-manifest`'s one-way invariant** (CI must never run less than the local static set). M-class findings that ask for a gate to be _added_ to `verify:cheap:internal` or to `verify:pr-local` are compatible with it; nothing here asks for a gate to be removed. Adding one is not free, though: `check:gate-manifest` parses the counts in `CLAUDE.md` ("36 static/consistency gates") and the gates skill ("check N of 39"), so the counts must move in the same change (Stage 5).
- **`check:diff-integrity` floors and `diff-integrity.json`.** Not to be raised to clear a diff.
- **Supabase migrations.** Two findings (M-class in §6, `set_document_corpus_access_mode` and `check:migration-history`) would be fixed by a migration or a script change. Merging a migration deploys to the live clinical database within seconds; those fixes go through an approved window with a validation guard migration, never as a side effect of this audit's PR.
- **Dead-looking code.** The knip lists (351 unused-export rows, 49 of them mockup noise), the six mockup exports in the calculators barrel, the three ward exports, the archived scripts still wired to npm commands, the dormant Clinical Ask tree and the Caring Contacts mockup are **triage candidates with evidence, not a delete list**. PR #2204 was walked back seven times for exactly this; `npm run check:dead-code-candidate -- --diff origin/main` is mandatory before any of them move, and 441 unchecked plan boxes currently pin most of the ward tree.
- **The five gate-parsed sections of `AGENTS.md`.** One finding (L18-F4, Low) shows the claim about them is itself inaccurate; that paragraph is not corrected in this PR because the safe change is to the gate's own documentation, which needs the gate author's decision.
- **Test files.** No test is skipped, deleted or quarantined by this audit. Two findings (L11-F1, L14-F1) are about tests that _stopped running_; the fix is to make them run.
- **The mockup corpus, Ward Flow sandbox, Care Plan prototype and Caring Contacts mockup.** Kept as they are. Retirement of the Caring Contacts mockup is a question for after Phase 2B.
- **Auto-merge, force pushes, pushes to `main`.** The PR for this audit is a draft with no auto-merge. Its own gate, stated for the record: the branch is **not** docs-only, because `data/repo-awareness-snapshot.json` is a route-payload input for `scripts/ci-change-scope.mjs`, so the diff classifies as heavy static, build, UI and coverage scope. The local gate is `npm run verify:pr-local` (20 steps, all offline: the docs and ledger checks, lint, typecheck, the full unit suite, a production build, the RAG fixture and medication checks), proven by its closing summary reading `failed: (none)` and `not reached: (none)`. While the PR is a draft, CI runs `static-pr`'s heavy steps, `PR Policy` and `PR mergeability` only; `safety`, `coverage`, `build`, `ui-critical(-fast)` and `caring-contacts-db` run when it is marked ready for review.
