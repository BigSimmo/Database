> **Correction (Stage 5, red team):** Merge into one finding. M17's trigger numbers are the wrong bucket: speech_transcription is 12/60 s for owners (api-rate-limit.ts:75) and 3/60 s anonymous (:96); '4/min anonymous, 20/min authenticated' belongs to clinical_ask. M16's numbers are correct.

- **Defect:** POST /api/speech/transcribe resolves `publicAccessContext` (never `requireAuthenticatedUser`) and forwards any audio file straight to OpenAI (`transcribeClinicalAskAudio`). The only gate is the `speech_transcription` rate limit (12/min owner, 3/min per hashed IP). `CLINICAL_ASK_ENABLED` is read only in `authority-registry.ts`; the transcribe route never consults it. The sole client caller, `use-clinical-ask-speech.ts`, is imported by nothing but its own test (`tests/clinical-ask-speech.dom.test.tsx`), so the endpoint has no product surface at all today. The route test at tests/speech-transcription-route.test.ts:74 is titled "authenticates and rate limits before transcription" but asserts only the rate limiter.
- **Trigger:** Any unauthenticated HTTP client POSTs multipart `audio` (≤10 MiB, allowed MIME) to /api/speech/transcribe on psychiatry.tools; or the operator sets CLINICAL_ASK_ENABLED=false expecting 'full rollback' per docs/openai-rag-operations.md:101-102.
- **Impact:** Unmetered-by-identity OpenAI spend from anonymous callers (3 × 10 MiB audio per minute per spoofable-adjacent IP; XFF right-edge trust is Railway-appended so spoofing is limited, but IPv6/NAT pools rotate freely). Arbitrary third-party audio (potentially containing patient identifiers) is relayed to a provider under the clinic's account with no user attribution in any log. The documented rollback control does not cover this provider call.
- **Proof:** not executed — traced: route.ts:20 `const access = await publicAccessContext(request, supabase)`; no `requireAuthenticatedUser`, no `clinicalAskModeEnabled` import. `grep -rn CLINICAL_ASK_ENABLED src` → env.ts:83 and authority-registry.ts:167,175 only. `grep -rln use-clinical-ask-speech src` → only the hook file itself. api-rate-limit.ts:75,96 → speech_transcription 12/60s (owner) and 3/60s (anonymous).
- **Fix sketch:** Require an authenticated session (`requireAuthenticatedUser`) on the transcribe route and short-circuit with 404/503 unless `clinicalAskModeEnabled(...)` is true for at least one mode; rename/extend the route test to assert a 401 for anonymous callers; either wire the speech hook into a governed composer or record it as a triage candidate (no importer found) per docs/agents/dead-code-deletion.md.
- **Skeptic (CONFIRMED):** Line-by-line trace holds. Guard search found no auth requirement (proxy, validation schema, rate-limit) and no CLINICAL_ASK_ENABLED consult on this route; the only anonymous control is 3 req/min per hashed IP. Two caveats the finder under-weights: anonymous callability is a repo-wide design (answer route :85 also uses publicAccessContext with an anonymous bucket), so the defect is specifically the missing master-flag gate + orphaned client hook, not anonymity per se; and the OpenAI spend is bounded by the rate limiter. Stays Medium: provider spend and third-party audio relay under the clinic's key with no user attribution, but no clinician-facing wrong output, no cross-owner data, no secret exposure. Fix sketch is safe for load-bearing surfaces; it would require updating the route test.
