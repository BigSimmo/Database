  (`{ tallies: {reason, count}[], totalCount, movementsWithDeclinesCount, movementCount, vocabularySize }`),
  rendered at `data-testid="ward-statistics-declines-by-reason"`.

**The exact shape to copy for a by-X breakdown (Figure 4's pattern):**

- Rows are generated by mapping over the full closed-vocabulary constant (`DECLINE_REASONS`), never
  hand-written — "a hand-written table checked by a hand-written test proves only that one author
  agreed with themselves."
- **Every member gets a row, including zero-count ones** — an omitted row is indistinguishable from a
  broken generator.
- `count` is typed `number`, not `number | null` — it's a genuine count.
- No ranking/sort by count ("the order is the vocabulary's own, not a ranking").
- `vocabularySize` returned so the row count is checkably equal to it.
- Tested in `tests/ward-statistics-derivations.test.ts`; a claims-register entry pins the exact
  source line.
- Empty state: not a special empty-state block — all rows render at 0 with `totalCount: 0`, same as
  any other count.

## 3. What the data actually supports

Two distinct "blocker" concepts exist and must not be conflated:

- `Movement.blocker: string` — free prose about a movement (referral/placement) being held up,
  gated through `hasActiveBlocker` in `ward-priority.ts`.
- `BedReleaseBlocker` — a closed, typed enum (`ward-change-reasons.ts:75-104`), used as
  `Admission.blockReason: BedReleaseBlocker | null` and as `BedRelease.blocker: BedReleaseBlocker | null`.

The enum:

```ts
export const BED_RELEASE_BLOCKERS = [
  "Awaiting clean",
  "Awaiting pharmacy",
  "Awaiting placement confirmation",
  "Awaiting service coordination",
  "Awaiting accommodation",
  "Awaiting transport",
  "Awaiting receiving-service acceptance",
  "Awaiting family or carer arrangement",
] as const;
```

**8 members**, counted directly from the array (matches the file's own comment "the owner-approved
list of eight").

## 4. Is the repair really in?

Yes. Current `ward-priority.ts:91-94`:

```ts
function hasActiveBlocker(blocker: string): boolean {
  const trimmed = blocker.trim();
  if (trimmed.length === 0) return false;
  return !BLOCKERS_MEANING_NOTHING_IS_BLOCKING.some((inactive) => inactive === trimmed);
}
```

This is a closed-set exact-match check (trimmed, case-sensitive equality against
`BLOCKERS_MEANING_NOTHING_IS_BLOCKING`, five members), replacing the old case-sensitive
literal+regex match. The repair is present on this branch.

**But this repair is irrelevant to Figure 3.** `hasActiveBlocker` only ever operates on
`Movement.blocker` (a referral being held up finding a bed). `ward-model.ts:73-74` states this in
terms: _"⚠️ `Movement.blocker` — the free-prose one. NOT `BedRelease.blocker`, the `BedReleaseBlocker`
enum that shares the name. Nothing here applies to that field."_ A "blocked discharges by blocker"
figure is about `Admission.blockReason` / `BedRelease.blocker` — a strictly-typed nullable enum
that needs no predicate function at all (`!== null` is the whole test, exactly as
`readyToLeaveCannot` already does it).

## 5. Null-versus-zero rule

`ward-statistics.ts:12-18` (exception, quoted):

> "**`null` means "nothing to average", and it must never be reported as `0`.** A ward with no
> discharges has no average length of stay — it does not have an average of zero days... the
> count-based figures (`readyToLeaveCannot`, `longStays`, `dischargeDateOutcomes`) are genuine
> counts, so `0` is a true and correct answer for them when there is no data."

For Figure 3: **every part of a blocked-discharges-by-blocker figure is a count.** A per-blocker
tally (how many blocked admissions/releases carry that blocker) and the total blocked count are
both genuine counts — `0` is correct and must render as `0`, not be omitted or nulled. There is no
averaging or rate anywhere in this figure's natural shape (unless the implementer adds one, e.g. "average
time blocked" — no instant exists to compute that duration, so it should not be attempted; see
`bedsBeingPrepared`'s doc comment for the identical reasoning about why no duration is recoverable
from a single shared provenance field).

## 6. Empty state

Copy Figure 4's pattern exactly: no special "absence" block. All 8 blocker rows render at `0` when
there are no blocked discharges; the total renders `0`. This is a count-based figure, not an
average, so it never hits the `absence`/`nothingToAverage` styles used elsewhere on this page for
genuinely unmeasurable figures (Figure 2, `arrivals.averageMinutes === null`).
