## 5. Executive determination

Ward Flow has strong correction behaviour but no durable control plane through which corrections reliably replace stale operational truth.

The current process structure is not fit for continued expansion. Replace the five-chat, transient-message, prose-ledger structure with:

- no orchestrator chat;
- one machine-readable local control plane;
- one writer per isolated worktree, or one writer total;
- generated human-readable views;
- current truth separated from immutable history;
- structured verification receipts;
- independently located restore-tested backups;
- clinical validation before further model-dependent work.

The present structure permits two careful agents to follow direct instructions and still produce contradictory outcomes.

## 6. Strongest case for preserving the current design

The present process has genuine strengths:

1. Parallel agents created substantial short-term throughput.
2. The offline synthetic boundary reduces external privacy and provider risk.
3. Mutation testing found defects that green tests missed.
4. Independent reviewers contradicted inaccurate implementation reports.
5. Correction commits openly record mistakes instead of silently hiding them.
6. Detailed briefs allow replacement sessions to resume after context loss.
7. The owner remains the source of product and clinical decisions.
8. The documents preserve valuable design reasoning and reversal costs.

These principles should be retained. They do not require five transient writing sessions, one shared index, manual custody, a prose orchestrator, 120 active documents, or multiple competing decision records.

# 8. Rule classification

Legend:

- `E`: enforceable now.
- `C`: cheaply enforceable.
- `D`: decoration or judgement only.

1. Product tests and selected invariants — E. Add collection and result-shape validation. Failure case: an empty or partial run looks green.
2. Verification coordinator — partial E. Add durable lease and receipt identity. Failure case: an unnecessarily broad gate blocks unrelated work.
3. Protected deletion — partial E. Add a cross-client guard and archive. Failure case: stale plans remain active forever.
4. One writer in a shared worktree — D. Replace with an exclusive writer lease or isolation. Failure case: agents are serialized without being isolated.
5. Separate worktree per writer — C. Enforce at bootstrap. Exempt genuinely read-only extraction.
6. Exact-path staging — C. Compare staged paths with a path-ownership manifest. Failure case: an incomplete manifest omits companion files.
7. Custody/baton — D. Replace with TTL leases. Failure case: a lost session creates a dead lock.
8. Single decision-ID allocator — D. Replace with generated IDs. Failure case: allocator loss blocks decisions.
9. Unique IDs and supersession — C. Use schema and graph validation.
10. Ledger current on governed line — C. Use generated drift checks rather than manual carry.
11. Computed implementation status — D moving to C. Resolve evidence mechanically. A touched file is not implementation proof.
12. Mandatory reports — D. Replace with structured events. Failure case: routine reports bury important events.
13. Direct-message reporting — D. Replace with a durable queue. Failure case: the recipient disappears.
14. Never ask whether work is done — D. Failure case: a lost completion message deadlocks work.
15. Complete question list — D. Use independent counterfactual review. Failure case: premature completeness suppresses alternatives.
16. Never present a menu — D. Treat as guidance. Failure case: the owner never sees genuinely different choices.
17. One authored home per fact — C. Use an ownership manifest. Failure case: rationale becomes fragmented.
18. Provisional-value marking — C. Use a typed expiry/review field.
19. Documentation in the same commit — C. Use a diff classifier. Failure case: large generated documentation increases conflicts.
20. Current/history separation — C. Enforce an archive boundary.
21. Pin command, commit, time, and artifact — C. Use an evidence schema.
22. Count before selecting — C. Use a query helper that reports the denominator. Eligibility can still be wrong.
23. Mutation/read-back/restore — C. Use a dedicated mutation harness. Do not mutate every low-risk literal.
24. Read passed count, not exit only — C. Reject zero collection and unexpected non-runs. Do not hard-code stale total counts.
