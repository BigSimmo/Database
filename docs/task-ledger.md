## Ownership

- [`outstanding-issues.md`](outstanding-issues.md) owns evidence and resolution history.
- [`operator-backlog.md`](operator-backlog.md) owns detailed provider-only and human-only actions.
- This file owns recommended order, acuity, capability, timing, effort, dependencies, approvals,
  success criteria, verification, and stop rules.
- Update the affected ledgers together when work is completed, dropped, superseded, or re-scoped.

Queue order is not authorization to call providers, spend money, change production, commit, push,
or deploy.

## Planning scales

- **A2 — important:** meaningful clinical, correctness, reliability, or evaluation-integrity work;
  it does not imply an active P0/P1 incident.
- **A3 — planned:** worthwhile work that can wait for its stated trigger.
- **Optional:** worthwhile only when its ownership, evidence, and cost trigger is satisfied.
- **Standard:** experienced generalist using an established pattern.
- **High:** senior engineer reasoning across multiple modules or runtime layers.
- **Specialist:** database, RAG, clinical-safety, privacy, or evaluation expertise; protected RAG work
  also needs an independent focused review.
- **Operator:** authorised human with the named provider, product, or clinical authority.

Effort is focused active work and excludes approval, CI, provider, scheduled-run, soak, and review
waiting time. Re-estimate only when a reproducer proves the safe scope is materially broader.

3. After scheduled evidence exists and approval to read it is given, perform TL-06 before protected

## Operating rules

- Revalidate the source issue and current `main` before starting a row.
- Use a task-specific branch/worktree, preserve unrelated changes, and run focused checks first.
- Ask before APIs, hosted CI, provider workflows, live-site measurement, production mutation, or paid
  checks. Local completion never implies provider approval.
- Stop at the named condition; do not create a broad refactor or speculative follow-up.
- On closure, record evidence in `outstanding-issues.md`, update this queue, and leave remaining
  provider work in `operator-backlog.md`.
